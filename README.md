![CI](https://github.com/mekit54567/uiboshki-bot/actions/workflows/ci.yml/badge.svg)

недели, баллы и сдача работ из СДО, дедлайны с напоминаниями, файлы курсов
по предметам и ИИ, который отвечает по лекциям группы. Бот
[@UiboshkiBot](https://t.me/UiboshkiBot) группы УИБО-03-24, РТУ МИРЭА.

## Что умеет

**📅 Расписание**
- главная: следующая пара с обратным отсчётом, пары на сегодня, погода;
  плашка «сегодня пары на МП-1, а не на В-78», если корпус не свой;
- неделя по дням: у каждой пары — баллы по предмету из СДО, а нажатие
  ведёт прямо в её текущий контроль;
- поиск расписания любого преподавателя, группы или аудитории МИРЭА, с
  закреплением; работает и с VPN, у бота свой справочник;
- если сайт МИРЭА лежит, бот показывает последнее сохранённое расписание с
  пометкой «данные от 14:20».

**🎓 СДО (Moodle) — своим входом**
- баллы БРС по каждому предмету: сколько до зачёта или «3/4/5», категории,
  пороги;
- текущий контроль: что зачтено, что ниже порога, что ждёт оценки; задания
  с описанием и файлами преподавателя;
- сдача работ прямо из приложения, до трёх файлов за раз;
- бот сам пишет, когда в СДО изменились баллы: «Моделирование: 34 → 39 (+5)»;
- вход хранится зашифрованным (Fernet), ключ от фразы старосты — отдельно от
  базы.

**📋 Дедлайны**
- общие из СДО (синк каждые 6 часов) и свои личные;
- своё напоминание к любому дедлайну: за день, за 3 часа, за час или своё
  время;
- кнопка «Сдать» у заданий СДО.

**📁 Файлы**
- сотни файлов курсов из СДО, разложенные по предметам и типам (лекции,
  практики, КР, методички);
- «скинь практику 3 по ООП» прямо в чате бота;
- `/tidyfiles`: «ЛК3_бизнес.pdf» превращается в «Лекция 3. Бизнес-процессы».

**🤖 ИИ по лекциям**
- чат и решалка (Gemini, запасной — DeepSeek) отвечают по лекциям группы:
  нужные подбираются под вопрос с учётом опечаток, падежей и сокращений
  («ООП», «матан», «SQL»);
- фото задачи → решение с объяснением; математика читаемая (x², √, ≤);
- знает расписание и дедлайны группы: на «что сдавать на неделе?» отвечает
  по делу.

**🔔 Уведомления — под себя**
- утром: пары, погода, другой корпус; можно выбрать дни и «только если есть
  пары»;
- перед парой — три сценария: первая пара дня (за 30 мин / 1 ч / 3 ч),
  после короткой перемены, после большого перерыва;
- дедлайны на ближайшие 3 дня.

**💬 В любом чате**
- inline-режим: набираешь `@UiboshkiBot` в любом чате и отправляешь туда
  расписание группы на сегодня, завтра или неделю — или расписание
  преподавателя по фамилии.

**👑 Для старосты**
- рассылки, ДЗ, заместители, статистика (`/stats`: картинка — сколько людей,
  что открывают, когда заходят);
- копия базы каждую ночь, восстановление из неё командой `/restore`.

**🎨 Само приложение**
- свои иконки, светлая и тёмная тема (как в Telegram, переключается на
  лету), знакомство при первом входе, капибара в пустых экранах.

## Как устроено

```
Telegram ──► bot.py (aiogram 3) ──┬─► handlers/      команды, чат, inline-режим
                                  ├─► scheduler.py    рассылки, напоминания, синк СДО, бэкап
                                  └─► webapp/server.py (FastAPI) ──► webapp/static/  Mini App
                       SQLite (database.py) · расписание МИРЭА (зеркало, ical)
                       СДО Moodle (sdo_*.py) · Gemini / DeepSeek (ai_solver.py)
```

- **Расписание**: официальный API МИРЭА из-за рубежа не отвечает, поэтому
  бот берёт ical с зеркала и сам собирает справочник преподавателей, групп
  и аудиторий (`schedule_index.py`).
- **WebApp**: авторизация по `initData` Telegram (HMAC); фронт — обычные
  скрипты без сборки (`webapp/static/js/*.js`).
- **Безопасность**: экран «Безопасность» в приложении объясняет простыми
  словами, что где хранится. Технически: шифрование входов СДО, подписанные
  ссылки на файлы на 10 минут, лимиты частоты, заголовки безопасности,
  ограничение размера запросов, CORS только на свой адрес.

Подробно для разработки — [CLAUDE.md](CLAUDE.md), история версий —
[CHANGELOG.md](CHANGELOG.md), план — [PLAN.md](PLAN.md).

## Запуск

```bash
pip install -r requirements.txt
python bot.py          # бот; с WEBAPP_URL — и Mini App в том же процессе (порт PORT, по умолчанию 8080)
```

Главные переменные окружения (полный список — `config.py`):

| Переменная | Зачем |
|---|---|
| `BOT_TOKEN` | токен бота (обязателен) |
| `STAROSTA_ID` | Telegram ID старосты, можно несколько через запятую |
| `WEBAPP_URL` | адрес Mini App (кнопки «Открыть приложение») |
| `GEMINI_API_KEY`, `DEEPSEEK_API_KEY` | ИИ; DeepSeek необязателен (запасной) |
| `SDO_SESSION_COOKIE` | вход старосты в СДО (дедлайны и файлы курсов) |
| `SDO_CRYPT_PASSPHRASE` | секретная фраза — ключ шифрования входов студентов |
| `ICAL_URL`, `GROUP_NAME`, `BOT_USERNAME`, `GROUP_PROGRAM` | своя группа (по умолчанию — УИБО-03-24) |
| `DATABASE_PATH` | где лежит SQLite |

## Тесты

```bash
pip install -r requirements-dev.txt
pytest          # ≈400 тестов, без сети
ruff check .    # линтер: неопределённые имена, лишние импорты
```

Тесты реальные, не заглушки: настоящая SQLite (временный файл на каждый
тест), настоящий роутинг aiogram через `Dispatcher.feed_update` (а не
прямые вызовы хендлеров: так однажды поймали баг с порядком регистрации,
который прямые вызовы не видели), настоящая HMAC-проверка подписи Telegram
WebApp, фронт проверяется через `node --check` и отрисовкой в браузере. В
сеть наружу (Telegram, Gemini, DeepSeek, СДО, МИРЭА) тесты не ходят: такие
вызовы подменяются точечно. CI (`.github/workflows/ci.yml`) гоняет тесты и
линтер на каждый push и pull request в `main`.

Тестами **не** покрыто: живые походы в Gemini, DeepSeek и СДО (проверяются
вручную на живом боте) и сами таймеры APScheduler (тестируются функции,
которые они вызывают).

## Мониторинг

`GET /health` — для внешнего аптайм-чекера. Если хендлер бота падает,
старосте приходит короткий алерт в личку (не чаще раза в 5 минут), см.
`bot.py`, `notify_starosta_on_error`.
