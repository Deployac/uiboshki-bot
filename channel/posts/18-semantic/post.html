Поиск по смыслу #обновление · ИИ-чат Раньше ИИ подбирал лекции по словам. Спросишь «почему нельзя просто сложить прибыль за все годы» — а в лекции это называется «дисконтирование» и «NPV». Общих слов нет — лекция не находится, и ИИ отвечает «из головы». Теперь бот ищет по смыслу — и под ответом пишет, откуда взял: «Лекция 5 · слайд 12». Нажал — открылась сама страница. Как текст превращается в смысл Каждый кусок лекции Gemini превращает в вектор — 768 чисел, координаты смысла. Близкие по смыслу тексты оказываются рядом, даже если слова разные. Искать ближайших соседей умеет сам SQLite — с расширением sqlite-vec: 
SELECT rowid, distance
FROM vec_chunks
WHERE embedding MATCH :вопрос
  AND k = 40
ORDER BY distance
distance — косинусное расстояние: чем меньше, тем ближе по смыслу. Два поиска лучше одного Смысл иногда промахивается на точных терминах, а слова — на перефразах. Поэтому бот ищет сразу двумя путями: по словам (FTS5, BM25) и по смыслу. А потом сливает списки: 
def rrf(*ranked):
  out = {}
  for r in ranked:
    for pos, cid in enumerate(r, 1):
      out[cid] = (out.get(cid, 0)
                  + 1 / (60 + pos))
  return out
Это Reciprocal Rank Fusion: важно место в списке, а не сырые баллы — BM25 и косинус в разных «единицах», складывать их напрямую нельзя. Кусок, который высоко в обоих списках, побеждает.
Ещё одна тонкость — разнообразие. Если три соседних слайда говорят об одном, они вытеснят всё остальное. Поэтому последний шаг — MMR (Maximal Marginal Relevance): каждый следующий кусок берётся не только самым подходящим, но и непохожим на уже выбранные. И не больше трёх кусков из одного файла.
Откуда «слайд 12» Лекции режутся не как попало, а по страницам PDF и слайдам презентаций. Короткие слайды вроде «Спасибо за внимание» склеиваются с соседними, длинные страницы режутся с небольшим перехлёстом — чтобы мысль не рвалась на стыке. Каждый кусок помнит своё место. ИИ получает куски с номерами [1], [2]… и ставит их прямо в ответе — номера тоже нажимаются. Где ещё пригодится Тот же рецепт — гибридный поиск в обычном SQLite — подходит для поиска по документам, заметкам, базе знаний, вопросам поддержки. Никаких отдельных серверов: один файл базы и одно расширение. Первый раз индекс собирается фоном — бот за ночь перечитывает 535 лекций и считает векторы в пределах бесплатных лимитов. Пока не досчитал — ищет по словам, но уже с нужной страницей. На скринах — стенд с тестовыми данными: ответ со ссылками и открытый слайд.
